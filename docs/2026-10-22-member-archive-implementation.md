# 회원 삭제·보관 구현

## 동작

- `PENDING`(승인 대기), `ACTIVE`(이용 중), `SUSPENDED`(이용 중지), `ARCHIVED`(삭제·보관)를 구분한다.
- DELETE는 Auth 계정을 지우지 않는다. 인증된 최고관리자 전용 `transition_member_archive` RPC로 상태·조직 멤버십 비활성화·감사 이력을 한 트랜잭션에서 처리한다.
- 자기 자신·최고관리자·조직의 마지막 활성 소유자·담당 리드가 있는 회원의 보관은 거부한다.
- 복구는 SUSPENDED이며 기존 조직 권한은 비활성 상태를 유지한다. 별도 승인 후 조직/역할을 명시적으로 다시 지정한다.
- 보관 계정의 재승인·안내 메일·등급 변경은 차단한다. 기본 목록과 승인 대기 집계에서 제외하고 보관함에서만 복구한다.

## 권한 경계

- 프록시는 모든 API에 계정 상태를 확인하며 조회 실패 시 차단한다. 로그아웃 경로는 항상 허용한다.
- 클라이언트 업무 레이아웃은 ACTIVE일 때만 자식을 마운트한다. 포커스·온라인·스토리지 이벤트·30초 주기로 재확인하고 보관/중지 감지 시 로컬 세션을 정리한다.
- DB RESTRICTIVE 정책은 기존 JWT도 현재 상태 및 활성 조직 멤버십으로 검사한다. 예전 역할만 남아 있다고 권한을 되살리지 않는다.
- 외부 Auth의 비동기 ban/unban은 적용하지 않는다. 늦은 보관 응답이 최신 복구·승인을 뒤집어 계정을 장기간 잠그는 경합을 피하기 위한 결정이다. Auth 공급자 자체의 토큰 발급 및 모든 기기의 갱신 토큰 폐기를 보장하는 설계는 아니다. 발급된 토큰이 업무 데이터 권한을 주지 못하도록 DB/API에서 차단한다.
- 공개 파일, 기존 서명 링크, 다운로드 완료 파일을 회수한다고 보장하지 않는다. 기존 소유자 권한 뷰·다른 SECURITY DEFINER 함수도 운영 적용 전에 별도 검토해야 한다.

## 마이그레이션 적용 전제

- 신규 SQL: `supabase/migrations/20261022030000_member_soft_archive.sql`.
- 운영 DB에는 적용하지 않았다. 실제 회원·조직·메일·기존 변경과 예약 작업 0건을 보존했다.
- 스키마 적용 없이 새 애플리케이션을 배포하면 상태 조회를 확인할 수 없어 접근을 차단한다. 반드시 별도 승인 후 격리 DB 검증 → 운영 스키마 점검/적용 → 새 코드 배포 순서를 지킨다.
- 조회 실패 시 기존 승인 여부로 권한을 우회해 활성화하지 않는다. 표시용 상태 변환의 기존 데이터 호환과 실제 접근 통제는 별개다.

## 검증

- 새 순수 상태/보관 RPC/API·기존 세션·업무 레이아웃·두 관리 화면 테스트를 추가했다.
- 신규 통합 테스트는 실행별 UUID 스키마와 합성 사용자만 사용한다. 운영 auth/users/public 데이터는 쓰지 않는다.
- Docker의 승인된 격리 DB 컨테이너 조회가 실패해 DB 실검증은 보류 상태다. 오프라인 SQL 문자열 검사와 목 테스트는 PostgreSQL 실행·교착·RLS 실효성 검증을 대체하지 않는다.
- 최종 순차 검증 결과는 `.local-state/release-20261022/archive-results.json` 및 단계별 로그를 확인한다. 결과 파일에 없는 단계는 완료로 취급하지 않는다.
- 최종 type-check → lint → test → build 모두 종료 코드 0. 테스트는 514건 통과, 기존 DB 11건과 신규 DB 9건 총 20건 건너뜀이다.
- 권한 승인된 Docker 컨테이너 읽기 전용 재확인도 ETIMEDOUT이었다. 신규 SQL의 실제 PostgreSQL 실행·동시성·가입 트리거 호환성은 아직 검증하지 못했으므로 운영 적용을 보류한다.

## 2026-10-23 후속 결과

Docker 런타임 통신 폴더를 승인된 비삭제 방식으로 재생성한 뒤 격리 DB가 healthy로 복구됐다. 전용 합성 스키마에서 기존 11건과 회원 보관 9건이 모두 통과했고 DB 게이트도 통과했다. 위 Docker 차단 기록은 당시 상태이며 현재의 DB 테스트 미실행을 뜻하지 않는다. 세부 증거는 `docs/2026-10-23-docker-runtime-recovery.md`를 따른다. 운영 스키마 적용/배포와 테스트에 포함되지 않은 동시성·기존 뷰/함수의 전체 호환성 검토는 별도다.
