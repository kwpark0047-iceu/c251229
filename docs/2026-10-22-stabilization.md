# 단계별 안정화 구현

## 릴리스 차이 기록

`node scripts/source-snapshot.mjs . tmp/presence-release-20261020`은 배포 대상 파일 경로·SHA-256 및 추가/변경/삭제 목록만 출력한다. 환경 파일·테스트·로컬 결과물은 제외하고 링크 경로와 활성 cron은 거부한다. 현재 release/baseline.json을 덮어쓰지 않는다.

위 비교 대상은 기존에 고정된 과거 릴리스 사본이며 최신 운영 배포라고 주장하지 않는다. 소스 해시는 배포 성공이나 검증 통과의 증거가 아니다. 운영 기준선 승격은 최신 배포 식별자와 해당 소스의 연결 확인 후 별도로 수행한다.

## 테마

색상 모드(light/dark)와 디자인 효과(glass/neo/antigravity)는 서로 다른 사용자 설정이므로 저장값을 강제로 합치지 않는다. 디자인 효과의 인라인 glass 색상이 공통 색상 모드를 덮어쓰는 문제, 이전 효과의 잔여 변수, 잘못된 저장값의 예외를 회귀 테스트로 재현하고 수정했다. neo 배경도 현재 모드의 bg-secondary를 사용한다. 실제 운영 브라우저의 시각 검증은 별도로 필요하다.

## 백업

관리자 인증과 RLS 경로를 유지하며 created_at 및 id로 정렬한 페이지를 조회한다. 서버가 페이지 크기를 제한해도 실제 반환 개수만큼 이동한다. 정확한 건수 누락·변경·중복 ID·빈 중간 페이지·조회 실패 시 부분 백업 파일 대신 실패를 반환한다. 서버 메모리 보호를 위해 테이블별 100,000건을 초과하면 명시적으로 실패한다.

페이지 간 동일 건수의 내용 변경이나 테이블 간 시점 일치까지 보장하는 트랜잭션 스냅샷은 아니다. 그 보장이 필요하면 별도의 DB 스냅샷 설계가 필요하다. 복원 API 동작은 변경하지 않았다.

## 격리 DB 및 배포 차단

Docker의 승인된 컨테이너 읽기 전용 조회가 10초 내 응답하지 않았다. 재시작·볼륨 삭제·WSL 종료는 수행하지 않았다. DB 테스트 20건의 실제 실행은 여전히 보류이며, 회원 보관 SQL의 운영 적용 및 배포도 보류한다.

운영 DB·스키마·실제 계정·메일·예약 작업은 변경하지 않았다. 기존 작업 파일 및 Git 기준선도 보존했다.

## 검증 증거

- 소스 검사 및 기존 릴리스 안전성 Node 테스트: 21건 통과.
- 신규 백업·테마 테스트: 실패 재현 후 7건 통과.
- 백업 API 통합 계약을 페이지 조회에 맞춰 보강하고 중간 페이지 실패의 다운로드 차단을 추가했다. 관련 통합/단위 27건 통과.
- 전체 테스트 첫 실행의 기존 목 계약 실패는 보완했다. 다음 실행의 메모리 부족 종료(134)는 별도 로그로 보존하고, 전역 설정 변경 없이 최종 실행의 Vitest worker만 2개로 제한했다.
- C: 여유 공간 약 156MiB가 관측됐다. Docker 장애/메모리 부족의 확정 원인은 아니지만 환경 위험으로 기록한다. 임의 정리·이동은 하지 않았다.
- 최종 순차 검증은 `.local-state/release-20261022/stabilization-results.json`과 단계별 로그를 기준으로 판단한다. databaseVerified=false를 유지하며 건너뛴 테스트를 성공으로 간주하지 않는다.
- 최종 type-check → lint → test → build 모두 종료 코드 0. Vitest는 522건 통과, DB 20건 건너뜀이다. 웹 소스 해시는 `464b3de3bc7bae5fcc74f06c17d1bacc63c0408d38f61560a9a8ff051753a0ae`이다.
- 빌드의 중첩 검증 사본 lockfile 경고는 남아 있다. 실제 운영 설정을 바꿔 숨기지 않았으며 별도 검증 사본의 루트 경계 정리가 후속 과제다.
