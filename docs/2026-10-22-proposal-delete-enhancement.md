# 최고관리자 제안서 삭제 고도화

## 변경

- 최고관리자에게만 표시되는 기존 삭제 아이콘에 눈에 보이는 `삭제` 문구를 추가했다.
- 제목 입력 확인, 삭제 중 중복 제출/취소 차단, 기존 서버 최고관리자 인증을 유지했다.
- 확인창의 Escape/Tab 처리를 dialog 내부 키보드 이벤트에 한정한 document listener로
  분리했다. 컨테이너 포커스에서도 Tab을 내부에 유지하고 처리 중 이탈을 막는다.
- 서버 삭제 성공 이후 화면 갱신 callback이 실패해도 삭제 확정 폼을 다시 보여주지 않는다.
  삭제 완료·첨부파일 경고를 유지하고 재삭제 대신 목록 새로고침을 안내한다.
- 목록 조회 무효화 callback을 재사용해 삭제 후 오래된 조회와 unmount 처리를 유지했다.
- `.next-admin-isolated` 자동 생성물만 ESLint 대상에서 제외했다. 소스 규칙은 완화하지 않았다.

기존 삭제 API와 Storage 경로 정책은 변경하지 않았다. 일반 회원 거부, 제목 확인,
동시 수정 충돌, 공유 첨부파일·외부 원본 유지, 파일/감사 후속 처리 경고는 기존
mock 회귀 테스트로 다시 검증했다. 실제 리드·인벤토리·제안서 삭제는 실행하지 않았다.

## 검증

Node 24.22.0 격리 런타임 사용. 최종 순서:

1. type-check 통과.
2. 전체 ESLint 통과 (오류/경고 없음).
3. Vitest 402건 통과, 격리 DB 11건 건너뜀. DB 연결 성공으로 계산하지 않는다.
4. 운영 환경 파일을 복사하지 않은 독립 사본의 Next.js 프로덕션 build 통과.

로그: `tmp/functional-audit-20261021/proposal-final2-results.json`,
`proposal-final2-{type,lint,test,build}.log`.
빌드 사본: `tmp/proposal-delete-build-20261021`.
웹 소스 713개 파일의 원본 해시는 사본 준비 후에도 모두 일치했다.
독립 npm ci는 install script 없이 lockfile 기준으로 실행했다.

처음 추가한 회귀 테스트는 4건 실패를 확인한 뒤 수정했다.
설치 병행 중 threads worker 시작 시간 초과가 발생해 설치 완료 후 forks 단일
프로세스로 다시 실행했다. ESLint 초기 플러그인 로딩 테스트의 30초 시간 초과는
해당 테스트만 기존 정책 검사와 동일한 60초로 맞췄다. 최종 테스트 실행 오류는 없다.

## 남은 제한

- Docker 컨테이너 조회가 15초 제한에서 ETIMEDOUT이었다. 재시작/볼륨 변경 없이 중단했다.
  DB 11건과 제안서 삭제의 실제 DB·Storage 실연동은 아직 검증하지 못했다.
- 빌드 사본이 작업 폴더 아래에 있어 Next.js의 다중 lockfile workspace root 경고가
  있었다. 빌드는 성공했지만 이 경고를 해결했다고 주장하지 않는다.
- 운영 DB·스키마·실제 계정은 변경하지 않았다. 예약 작업 crons 빈 배열 유지.
- 배포하지 않았으므로 wemarketad.vercel.app에 이 변경이 반영됐다는 의미가 아니다.
