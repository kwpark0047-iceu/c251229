# 기능별 오류 점검 1차 결과

## 범위와 보존

현재 작업 폴더를 Node 24.22.0으로 점검했다. 이전 운영 릴리스 후보의 통과 결과를
현재 작업 폴더의 검증 결과로 대신하지 않았다. 기존 수정 파일과 운영 DB·스키마·
실제 계정은 변경하지 않았다. 예약 작업 설정도 변경하지 않았다.

## 실행 결과

로그 디렉터리: `tmp/functional-audit-20261021`.

- type-check: 종료 코드 0.
- lint: 종료 코드 1. 오류 15건, 경고 8건.
- test: 종료 코드 1. 54개 파일 중 52개 통과, 2개 실패.
- 테스트 단위: 379건 통과, 1건 실패, 11건 실행되지 못함.
- 격리 DB fixture 시작 전 Docker 컨테이너 확인이 ETIMEDOUT으로 실패했다.
  후속 docker info도 응답하지 않아 해당 조회 명령만 중단했다.
- 앞 단계가 실패해 build 및 배포는 수행하지 않았다.

## 기능별 판단

### 회원 승인·삭제

제공된 운영 로그는 승인 PATCH 500을 확인하지만 DB 오류 원문/코드가 없다.
회원 승인 API도 update 오류를 로그 없이 일반 메시지로 반환한다.
컬럼 누락, 권한 또는 트리거 오류 중 무엇인지 확정할 수 없다.
안전한 오류 분류/추적번호 보강을 제안했으며 설계 승인을 요청했다.
운영 회원 승인 요청은 재현하지 않았다. mock 테스트 통과는 운영 DB 정상의 증거가 아니다.

### 제안서

ProposalDeleteDialog의 dialog 키 이벤트가 접근성 규칙 경고를 발생시킨다.
ProposalsView의 loadSequence.current cleanup이 Hook 규칙 경고를 발생시킨다.
기존 접근성 정책 테스트가 이 두 경고를 실제로 검출해 실패했다.

markProposalSent는 제안서 SENT 저장 후 updateLeadStatus를 호출한다.
CONTACTED/CONTRACTED에서 PROPOSAL_SENT로의 역행은 상태 검증기가 거부한다.
따라서 실제 상태 역행으로 단정하지 않는다. 다만 제안서 저장 후 실패 응답하는
부분 성공과 재시도 혼선 위험은 별도 회귀 테스트가 필요하다.

### 리드·공공데이터·업무보드·기타

실행된 테스트에서 추가 assertion 실패는 확인되지 않았다. 외부 API·이메일 mock이
포함되므로 운영 API 키 유효성이나 실서비스 전체 정상 동작을 의미하지 않는다.
격리 DB 11건도 이번에는 성공으로 계산하지 않았다.

### 공통 검사 기반

.next-admin-isolated 자동 생성물이 ESLint ignore에서 누락됐다.
오류 15건과 생성물 경고 6건의 원인이다. 규칙을 끄거나 플러그인 버전을
바꾸기보다 이 특정 빌드 출력 폴더를 제외하고 회귀 테스트를 추가하는 것이 적절하다.

## 권장 반영 순서

1. 생성물 제외 정책과 회귀 테스트, 제안서 접근성/cleanup 경고 수정.
2. 회원 승인 오류의 코드 기반 비식별 로그 및 사용자 안내, mock 실패 회귀 테스트.
3. Docker 복구 범위를 별도 확인하고 격리 DB 11건 재실행. 볼륨 삭제/초기화 금지.
4. 제안서 발송의 부분 성공/중복 발송 방지 계약을 정하고 회귀 테스트로 수정.
5. 전체 type-check → lint → 격리 DB 포함 test → 안전한 격리 사본 build 재검증.

수정·배포 완료 보고가 아닌 1차 진단 결과이며, 업무 동작 변경 설계 응답을 기다린다.
