# 승인 안내 이메일 오류 진단

## 확인 사항

- 운영 로그에서 `RESEND_API_KEY is missing`을 확인했다. 변수 이름이 등록되어 있다는 것만으로 기존 배포의 실행 환경에 유효한 값이 있다고 판단할 수 없다.
- 승인용 공통 메일 서비스는 `RESEND_FROM_EMAIL`과 `RESEND_FROM_NAME`을 사용하지 않고 `notifications@wemarket.subway`를 고정 사용했다.
- 로컬 설정의 키로 Resend 도메인 목록을 읽기 전용 조회한 결과 HTTP 400 / validation_error였다. 키나 수신자 정보는 출력하지 않았다.
- 사용자는 운영 설정을 유효한 값으로 갱신했다고 확인했다. 값은 직접 열람하거나 다른 값으로 덮어쓰지 않았다. 환경변수 변경 반영에는 새 배포가 필요하다.

## 수정

- 발신 주소와 표시 이름을 서버 환경변수에서 읽는다. 가짜 키·고정 발신 도메인 대체 동작을 제거했다.
- 설정 형식을 먼저 확인하여 누락·공백·잘못된 발신 주소·헤더 개행이 있으면 외부 발송을 호출하지 않는다.
- 수신자나 키가 포함될 수 있는 외부 오류 원문을 로그에 남기지 않는다.
- 제공기관 메시지 ID가 없으면 성공으로 표시하지 않는다.
- 승인 안내 재전송은 설정 오류 503, 제공기관 실패 502로 구분하고 승인 상태는 유지됨을 안내한다.
- 기존 예약 작업의 반환 타입 호환성을 보존했다. 예약 작업 설정은 변경하지 않는다.

## 검증 경계

- 신규 메일 테스트 9건은 수정 전 모두 실패, 수정 후 통과했다. 관리자 API와 합쳐 관련 테스트 44건이 통과했다.
- 순차 검증 결과: `.local-state/release-20261022/email-fix-results.json` 및 단계별 로그.
- 운영 DB·회원·예약 작업·발신 도메인 DNS는 변경하지 않았다. 실제 회원에게 테스트 메일을 발송하지 않았다.
- 운영 키의 유효성·도메인 인증·수신함 배달 성공은 목 테스트로 보장하지 않는다. 실제 발송 검증은 수신자와 범위를 별도 승인받아야 한다.
- 최종 순차 검증: type-check, lint, test, build 모두 종료 코드 0. 테스트 476건 통과, 격리 DB 11건 건너뜀. 이번 수정은 아직 운영에 배포하지 않았다.
