# 계정 접근 가드의 지연 응답 경쟁 수정

## 재현한 오류

1. 외부 로그아웃 알림을 구독하지 않아 포커스/주기 조회 전까지 업무 UI가 남았다.
2. 이전 계정의 느린 상태 조회가 새 로그인 이후 완료되면 이전 계정 상태를 표시하거나 새 로컬 세션에 signOut을 호출할 수 있었다.
3. 컴포넌트 이탈 후 조회가 완료되면 UI 변경은 막았지만 signOut 부작용은 실행했다.

기존 코드에서 회귀 테스트 3건이 실제로 실패하는 것을 확인했다. 운영 계정은 사용하지 않았다.

## 수정 경계

- 인증 이벤트에서 요청 세대(epoch)를 무효화하고 콜백 밖의 타이머에서 상태를 확인한다.
- 로그아웃은 즉시 업무 UI를 제거한다. 계정이 바뀌면 새 상태 확인 전까지 업무 UI를 마운트하지 않는다.
- 같은 계정의 토큰 갱신은 입력 중인 자식 화면을 불필요하게 재마운트하지 않는다.
- 늦은 응답과 화면 이탈 후 응답은 무시하며, 로컬 signOut 직전에도 현재 사용자 신원을 다시 확인한다.
- 이전 요청이 끝나지 않아도 새 계정의 확인을 시작할 수 있다. 구독·예약된 타이머는 이탈 시 해제한다.
- DB/RLS 및 서버 인증은 그대로 유지한다. 클라이언트 가드는 서버 권한 통제를 대체하지 않는다. 이미 시작된 Auth API의 취소나 모든 기기의 토큰 폐기를 보장하는 변경은 아니다.

## 검증

- 가드/프록시/보관 API 관련 21건 통과.
- 계정 전환·지연 응답·이탈·로그아웃·동일 계정 토큰 갱신은 합성 사용자와 목 응답으로 검증했다. 실제 브라우저/운영 로그인 및 PostgreSQL 검증을 대신하지 않는다.
- 최종 순차 검증 결과는 `.local-state/release-20261022/account-guard-results.json`에 기록한다. 실제 DB 검증 전까지 databaseVerified=false를 유지한다.
- 최종 type-check → lint → test → build 모두 종료 코드 0. Vitest 528건 통과, DB 20건 건너뜀, 별도 로컬 도구 테스트 41건 통과다. 현재 배포 대상 파일과 검증 사본의 차이는 없으며 해시는 `16e567da8cf8245f9b398fde2a80f2a28d61ecddf8044b0f05c6af9424e57839`다.
- Docker 정상 시작 시간 초과로 DB 테스트 20건은 별도로 보류 중이다. 운영 DB·스키마·계정·메일·배포와 예약 작업은 변경하지 않는다.
- 사용자는 Desktop이 시작 중 또는 오류 안내 상태라고 답했다. 정확한 안내 문구를 추가로 요청했으며, 원인 확인 없이 강제 재기동/수리를 반복하지 않는다.

## 후속 환경 복구

이후 오류 화면의 dockerInference 런타임 소켓 문제를 확인하고 별도 승인으로 run 폴더를 백업·재생성했다. 격리 DB 테스트 20건은 실제로 통과했다. 앞선 Docker 차단 기록은 과거 상태이며 최신 전체 검증은 `.local-state/release-20261022/recovered-results.json`을 따른다. 운영 적용은 수행하지 않았다.

최신 순차 검증은 type-check/lint/test/build 모두 통과했으며 DB 포함 Vitest 548건 통과·건너뜀 0건, 도구 테스트 41건 통과다. 앞선 528건 통과/20건 보류 기록은 복구 전 결과다. 실제 브라우저 검증·운영 스키마 적용·배포는 여전히 별도다.
