# 기능별 점검 및 회귀 오류 수정

## 진행 방식과 경계

현재 작업 폴더의 기존 기능을 파일별 테스트 결과로 분류하고, 새 경계값/수명 테스트에서
실패한 지도·인근역 코드부터 수정했다. 운영 환경에 직접 승인·삭제·동기화 요청은 보내지 않았다.
전체 기능의 실서비스 종단간 검증이나 모든 오류 해결을 완료했다는 보고가 아니다.

## 재현 후 수정한 오류

### 인근역 좌표 검증

- 입력 또는 역사 좌표가 Infinity이면 기존 truthy 검사와 거리 상한 검사로 걸러지지
  않아 잘못된 역/NaN 거리가 선택될 수 있었다.
- 숫자 타입, 유한성, WGS84 범위 공통 검증기를 추가했다.
- 잘못된 입력은 추천하지 않고, 잘못된 역사 데이터는 건너뛴다.
- 기존 거리 기반 선택과 3km 추천 반경을 유지했다. 상위 3개 추천 UI나 저장 데이터
  자동 재계산은 추가하지 않았다.

### 지도 포커스와 이탈

- 기존 hasProcessed 플래그가 2초 동안 새 검색 이동을 막았다.
- 이전 완료 타이머가 새 선택이나 화면 이탈 이후에도 실행될 수 있었다.
- 좌표 변경에 맞춰 이동하고 이전 타이머를 cleanup에서 취소한다.
- 완료 콜백 ref로 최신 콜백을 사용하면서 불필요한 렌더의 타이머 재시작을 피한다.
- MapView의 중심·마커·검색 대상에도 잘못된 좌표가 들어가지 않도록 필터를 보강했다.
- 실제 운영 지도 표시 오류의 원인과 같다는 것은 아직 입증하지 못했다.

최초 재현: 10개 중 9개 실패. 수정 후 10개 모두 통과.
추가 WGS84 경계/타입 테스트 16개를 포함해 새 회귀 테스트 26개가 통과했다.

## 최종 순차 검증

- Node 24.22.0 전용 런타임 사용. 전역 Node·사용자/시스템 PATH는 변경하지 않았다.
- type-check 통과.
- 전체 lint 통과.
- 로컬 도구 테스트 29개 통과.
- 전체 Vitest 428개 통과, 11개 미실행. 실행된 테스트의 실패/처리되지 않은 오류 없음.
- 새 독립 사본의 프로덕션 build 통과.
- Chromium 기본 동작 3개 통과: 랜딩, 보호 경로 로그인 이동, 미인증 cron 차단.

빌드 사본은 `tmp/functional-audit-build-20261022`이며 운영 .env를 복사하지 않았다.
동일한 package.json/lockfile의 기존 검증용 node_modules를 별도 디렉터리에 독립 복사했다.
설치 트리를 공유하는 junction이나 전역 설치 변경은 사용하지 않았다.
빌드의 공개 Supabase 설정은 가짜 루프백 값이므로 이 사본을 운영 배포용 산출물로 사용하면 안 된다.
Next.js의 중첩 lockfile workspace root 경고는 남아 있지만 빌드는 성공했다.

## 남은 위험과 다음 순서

1. Docker 컨테이너 조회가 15초에서 ETIMEDOUT이다. 볼륨 삭제·초기화·강제 재시작 없이
   멈췄다. 격리 DB 11개와 실제 DB·Storage 권한 검증을 우선 복구해야 한다.
2. 운영 회원 승인 500은 이전에 추가한 비식별 오류 진단이 아직 미배포여서 원인이 미확정이다.
   권한 우회나 운영 컬럼 변경으로 임의 처리하지 않는다.
3. 실제 지도 타일·로그인 이후 업무 화면, 외부 API 키·메일 발송은 별도 승인된 합성
   환경/브라우저 검증이 필요하다. 이번 브라우저 3개는 업무 화면 전체 검증이 아니다.
4. 인벤토리 역명 도면 팝업·상위 여러 인근역 추천 등 미승인 신규 기능은 이번에 추가하지 않았다.

기존 작업 변경, 운영 DB·스키마·실제 계정을 보존했고 crons 빈 배열을 유지했다.
커밋·배포는 하지 않았다.
