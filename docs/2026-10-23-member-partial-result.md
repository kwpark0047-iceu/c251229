# 회원 처리 부분 성공 안내 수정

## 재현 및 원인
서버는 회원 상태 저장 후 이력·메일 실패를 warnings로 반환한다. 기존 클라이언트는 message와 warnings를 하나의 문자열로 합쳤고 확인창은 success=true만 보고 닫혔다. 따라서 후속 처리 실패가 일반 성공 토스트에 섞이거나 확인하기 어려웠다.

회귀 테스트에서 경고 alert가 없고 확인창이 자동으로 닫히는 문제를 재현했다. 응답 경고가 배열이 아닌 경우에는 문자열 펼치기 오류가 연결 실패로 오인될 수도 있었다.

## 수정
- 회원 요청의 성공 메시지와 후속 경고를 별도 필드로 유지한다.
- 승인/취소/보관/복원 확인창에서 완료 상태와 후속 경고를 분리해 표시한다.
- 경고가 있으면 자동 닫기를 하지 않고 명시적 닫기를 제공한다.
- 완료 후 상태 변경 버튼은 제거한다. ‘목록 다시 불러오기’는 목록 조회 콜백만 실행하며 회원 변경 API를 재실행하지 않는다.
- 경고가 있는 완료 알림은 성공 토스트가 아니라 경고 토스트로 구분한다.
- 경고가 없는 기존 완료 콜백의 1개 인수 계약과 자동 닫기는 유지한다.
- 잘못된 경고 자료형은 메시지 합치기 오류를 일으키지 않도록 검증한다.

## 검증 범위
회원 확인창/대시보드/응답 파서 관련 18건 통과. 운영 회원이나 메일은 사용하지 않았다. 신규 회귀 3건을 포함한다.
전체 파이프라인 기록은 .local-state/release-20261022/member-result-results.json을 따른다. 완료 전 기록을 최종 증거로 취급하지 않는다.

## 남은 위험
이 변경은 이메일 제공자 설정이나 이력 저장 DB 계약 자체를 수정한 것이 아니다. 경고의 원인 해결은 별도이며 회원 상태를 다시 변경해서 해결하려고 하면 안 된다.
서비스 등급 변경 등 다른 작업의 공통 결과 UI 확장과 실제 브라우저 E2E는 남아 있다. 운영 스키마 호환성 확인 전 전체 작업 폴더 배포는 금지한다. 운영 DB·스키마·계정·예약 작업은 변경하지 않는다.

## 추가 경로 점검
별도 UserManagementView의 완료 콜백에서도 경고를 성공으로 표시하는 문제를 재현하여 동일하게 수정했다. 두 진입 화면을 대상으로 부분 성공은 경고 알림, 확인창 유지, 성공 알림 미실행을 검사한다. 추가 경로 테스트 13건 통과(두 화면 부분 성공 신규 2건 포함).

중간 검증에서 소스 변경 감지 게이트가 빌드를 차단했다. 최종 수정본의 파이프라인은 member-final-results.json으로 새로 기록한다. member-result-results.json은 중간 자료이며 최종 통과 증거가 아니다.
