# 기능별 재점검

## 안전 경계

- 운영 DB, 스키마, 실제 회원 및 메일 발송을 변경하지 않는다.
- 기존 변경을 보존하고 `vercel.json`의 `crons: []`를 유지한다.
- 검증은 운영 환경 파일을 복사하지 않은 `tmp/security-patch-20261022`에서 수행한다.
- 외부 API, 메일, AI는 테스트 대역을 사용한다. 모의 검증은 실서비스 검증과 구분한다.

## 재현 및 수정

1. 업무 조회 날짜를 `toISOString()`으로 생성하면 한국 시간 자정 직후 전날을 조회한다. 월간 조회도 월초·월말을 하루 앞당긴다. 사용자의 달력 연·월·일로 날짜 문자열을 생성하도록 수정했다. UTC 완료 시각 기록은 유지한다.
2. 완료 업무를 미완료·진행 중·취소로 전환할 때 `completed_at`이 남는다. 비완료 상태 변경 시 명시적으로 `null`을 저장하도록 수정했다.

## 후속 위험 분석

- 백업 GET은 테이블별 단일 select만 사용한다. 데이터가 Supabase 반환 상한을 넘을 때 완전한 백업인지 페이지네이션 및 대량 합성 데이터로 확인해야 한다. 현재 테스트 통과만으로 복원 완전성을 보장할 수 없다.
- 도면 업로드 API는 브라우저용 서비스를 호출한다. 서버 인증 전달 및 Storage RLS 동작은 격리 계정 기반 검증이 필요하다. 권한을 우회하는 수정은 하지 않았다.
- 모든 기능의 운영 정상 동작이나 전체 코드 커버리지 80%를 달성했다고 판단하지 않는다. 모의 테스트, 실제 DB 테스트, 브라우저 검증 결과를 별도로 보고해야 한다.
