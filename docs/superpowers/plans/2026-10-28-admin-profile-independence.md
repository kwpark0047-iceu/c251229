# 최고관리자 프로필 조회와 조직 조회 분리

## 확인된 코드 결함과 수정 범위
getCurrentUser는 조직 조회 오류가 발생하면 profiles를 읽기 전에 null을 반환했다. page.tsx는 null과 미승인을 모두 승인 대기로 표시했다. 운영의 실제 남은 실패 원인은 아직 확인되지 않았으며 이 결함이 유일한 원인이라고 단정하지 않는다.

DB 프로필을 먼저 검증하고 조직 조회를 별도로 제한 시간 안에 수행한다. DB에서 is_super_admin=true AND account_status=ACTIVE를 확인한 경우에만 조직 조회 실패와 무관하게 전역 관리자 정보를 반환한다. 조직 실패 시 조직/역할/일반 권한은 부여하지 않는다. 일반 계정의 조직 조회 실패 및 프로필 조회 실패는 null로 유지하며 user_metadata의 관리자 주장을 신뢰하지 않는다. 최고관리자라도 PENDING/SUSPENDED/ARCHIVED는 관리자 권한과 이용 승인을 반환하지 않는다.

사용자 정보 조회 중/조회 실패/실제 승인 대기/그 밖의 이용 제한 안내를 분리한다. 운영 DB, 실제 계정, RLS, cron 설정은 변경하지 않는다. 기존 로그인 호환용 생성 컬럼은 완전한 회원 보관 기능을 의미하지 않는다.

## 테스트
기존 코드에서 ACTIVE 최고관리자 + 조직 조회 오류 케이스가 실패함을 재현했다. 새 회귀 6건 및 안내 분기 2건을 추가했다. 격리 검증 사본에서 type-check/lint/로컬 도구/전체 테스트/필수 DB 게이트를 통과했다. 전체 581건 통과, 실패 0, 건너뜀 0. 빌드 결과는 최종 영수증에서 확인한다.
