# 단계별 안전 반영 계획

## 목표와 경계
기존 변경을 보존하며 검증된 코드와 최신 작업 코드의 차이를 식별한다. 운영 DB·스키마·실제 계정·메일은 변경하지 않고 cron=[]를 유지한다. 과거 배포 기준선은 덮어쓰지 않는다.

## 1. 검증 기준선 고정
- [x] 현재 배포 대상 파일의 해시 목록을 로컬에 저장한다(비밀값 제외).
- [x] 소스 해시와 검증 영수증을 대조하는 읽기 전용 도구를 테스트 우선으로 구현한다.
- [x] 실패·누락 단계, 격리 DB 미검증, 최신 소스 불일치에서 실패하도록 한다.

## 2. UI 회귀 검증
- [x] 상단 높이와 카드 버튼 레이아웃 회귀 테스트를 유지한다.
- [x] 자동 검사와 실제 브라우저 시각 검증을 구분한다.

## 3. 전체 검증과 호환성 경계
- [x] type-check → lint → 격리 DB 포함 test → build 순서로 검증한다.
- [x] 운영 스키마 의존 변경은 UI/로컬 도구와 분리한다.
- [x] 실행하지 못한 항목은 완료로 기록하지 않는다.

## 배포 기준
이번 작업에서는 배포하지 않는다. 승인된 릴리스만 별도 스냅샷으로 만들며 회원 보관 마이그레이션의 운영 호환성 확인과 승인 전에는 전체 작업 폴더를 운영 배포하지 않는다. 소스 목록은 배포 성공이나 실제 브라우저 검증의 증명이 아니다.
