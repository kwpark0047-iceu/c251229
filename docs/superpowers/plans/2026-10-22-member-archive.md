# Member Archive Implementation Plan

**Goal:** 회원 삭제를 영구 삭제 대신 권한 차단 및 이력 보존으로 전환한다.

**Architecture:** DB 상태·조직 멤버십 비활성화·이력 저장은 인증된 최고관리자 전용 트랜잭션 RPC로 처리한다. 기존 승인 여부와 새 상태를 일관되게 동기화하고, API·RLS·UI가 보관 상태를 확인한다. 복구는 이용 중지이며 자동 재승인은 없다.

**Tech Stack:** Next.js 16, React 19, Supabase PostgreSQL/Auth, Vitest.

## Global Constraints

- 기존 변경 보존. 운영 DB 적용, 실제 계정 조작, 메일 발송, 배포 금지.
- 예약 작업 0건 유지. 로컬 격리 DB 외 실연동 금지.
- 보관 이후 기존 JWT도 DB 접근을 차단한다. 이미 다운로드된 파일 회수나 기존 서명 URL 즉시 폐기는 보장하지 않는다.

## Tasks

- [ ] 상태 분류·보관 RPC·접근 차단 회귀 테스트를 먼저 추가한다.
- [ ] 신규 마이그레이션으로 상태·멤버십 비활성화·원자적 감사 이력·제한 정책을 구현한다.
- [ ] 회원 DELETE를 보관 RPC로 교체하고 복구를 추가한다. 영구 삭제 경로 제거.
- [ ] 외부 Auth ban/unban 경합을 피하고 DB·API 차단을 원자적으로 적용한다. 열린 탭은 로컬 세션을 정리한다.
- [ ] 인증·API 가드에 보관/이용 중지 상태 검사를 연결한다.
- [ ] 두 회원관리 화면의 상태 집계·보관함·복구·대화상자 문구를 통일한다.
- [ ] 합성 데이터로 중복 요청·최종 소유자·담당 리드·복구 및 거부 상태를 검증한다.
- [ ] type-check → lint → test → build를 순차 실행하고 DB 미검증 범위를 구분한다.

## Migration And Rollout

스키마 적용 전 새 코드를 운영 배포하지 않는다. 별도 운영 적용 승인과 대상 확인 후 DB 마이그레이션 → 스키마 확인 → 애플리케이션 배포 순서로 진행한다. 롤백 시 보관 계정을 다시 활성화하지 않는다.
