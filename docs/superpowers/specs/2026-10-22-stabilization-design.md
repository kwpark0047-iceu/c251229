# 승인된 안정화 설계

## 범위

사용자가 승인한 단계 순서: 릴리스 차이 기록 → 격리 DB 검증 → 테마 및 백업 오류 수정 → type-check/lint/test/build. 운영 스키마 적용과 배포는 별도 승인 대상이다.

## 경계

- 릴리스 검사 도구는 경로와 해시만 기록하며 소스·비밀값을 보고서에 내보내지 않는다. 기존 고정 기준선은 변경하지 않는다.
- 격리 DB는 기존 연결 안전성 검사와 실행별 합성 스키마를 사용한다. Docker 장애 시 데이터 삭제나 강제 복구 대신 보류한다.
- 색상 모드는 ThemeProvider/CSS가, 디자인 효과는 design-tokens가 소유한다. 서로 다른 저장값은 보존하며 모드 소유 색상 변수를 디자인 효과가 덮어쓰지 않는다.
- 백업은 인증/RLS를 유지하고 실제 반환 개수로 다음 페이지를 계산한다. 정확한 건수와 ID를 검사하고 일부 페이지가 실패하면 다운로드 전체를 실패시킨다. 테이블별 상한은 100,000건이다.
- 백업은 여러 요청으로 구성되므로 단일 트랜잭션 스냅샷 일관성은 보장하지 않는다.

## 완료 기준

실행된 회귀 테스트로 실패/성공을 확인하고 품질 검증은 지정된 순서로 실행한다. DB 테스트 미실행·건너뜀은 통과로 취급하지 않으며 회원 보관 SQL 운영 적용과 배포를 차단한다. 기존 변경과 예약 작업 0건을 보존한다.
