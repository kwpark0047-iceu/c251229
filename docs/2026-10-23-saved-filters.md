# 개인 저장 필터 1차 구현

## 사용자 동작
리드 화면의 통계 아래 ‘내 필터’에서 현재 조건에 이름을 붙여 저장한다. 저장한 이름을 누르면 적용하고 각 항목의 삭제 버튼으로 제거한다. 최대 10개, 이름 1~24자이며 중복 이름은 거부한다.

## 저장 범위
업종·서울/경기·회원이 선택한 리드 상태·그리드/목록/지도 보기·미접촉 조건·스코어 정렬만 저장한다. 검색어·리드 개인정보·세부 서비스·날짜·페이지는 저장하지 않는다. 필터 이름은 사용자가 직접 작성하므로 개인정보를 이름에 넣지 않도록 사용해야 한다.

적용 시 검색어/세부 서비스/페이지/역 자동완성을 초기화하며 날짜는 현재 선택을 유지한다. 날짜는 저장 필터에 포함되지 않는다.

## 안전 경계
- 계정 ID와 조직 ID를 조합한 브라우저 localStorage 키로 목록을 구분한다.
- 조직 변경 시 컴포넌트를 재생성하여 이전 목록 노출을 방지한다.
- 이는 브라우저 편의 설정의 네임스페이스 분리이며 암호화/서버 권한 제어를 대체하지 않는다. DB·조직 접근은 기존 서버/RLS를 따른다.
- 브라우저/기기 간 동기화는 없고 같은 기기의 다른 탭 저장 변경은 storage 이벤트로 갱신한다.
- 잘못된 JSON·허용되지 않은 조건·중복 ID·잘못된 자료형은 사용하지 않는다.
- 저장/삭제가 실패하면 성공으로 처리하지 않는다.
- 다른 탭과의 동시 저장은 localStorage의 한계상 트랜잭션을 보장하지 않으며 마지막 쓰기가 우선한다.

## 검증
새 단위/컴포넌트 테스트 7건: 계정/조직 구분, 허용 속성만 저장, 손상 데이터/잘못된 enum/배열 자료형 거부, 최대 개수·중복·이름 검사, 저장/적용/삭제, 계정 변경, 저장 공간 오류.
최종 순차 파이프라인 결과는 .local-state/release-20261022/filters-results.json을 따른다. 진행 중 영수증을 완료 증거로 취급하지 않는다.

## 남은 범위
최근 리드/제안서 작업 복원과 자동 마지막 화면 복원은 미구현이다. 개인정보·권한 재검사·입력 중 덮어쓰기 방지 설계를 별도로 적용한다. 공통 오류 안내·회원 타임라인, 제안서 임시저장, 동기화 결과 센터, 업무 시작 화면도 후속 단계다. 운영 배포와 운영 스키마 변경은 수행하지 않았다.

최종 검증: type-check → lint → 격리 DB 포함 test → build 모두 종료 코드 0. Vitest 555건 통과/실패 0/건너뜀 0, DB 필수 20건 포함. 로컬 도구 48건 통과. 현재 소스와 검증 사본 및 영수증 해시 일치: e76702e6076681a0b95874072309a78e8d4e0f2c8c46ef883f72ee7c20d1227d. 신규 필터 실제 앱 브라우저 E2E와 운영 배포는 미실행이다. 운영 DB·스키마·실제 계정·메일을 변경하지 않았으며 cron=[] 유지.
